# Minecraft Regret Study

## Overview

This repository contains materials for a Minecraft-based decision-making study examining regret, counterfactual feedback, and learning. Participants complete repeated trials in which they choose a block to mine and receive an outcome. On some trials, participants pre-select possible blocks before making their final choice, which allows analyses of how regret depends on what they received compared with what they could have received.

The current analysis file is `Minecraft.Rmd`.

## Current Analysis File

`Minecraft.Rmd` is an exploratory R Markdown file. It loads the processed dataset, visualizes key trial-level patterns, and runs early mixed-effects models predicting regret.

Current sections include:

1. Regret over trial index
2. Regret by actual outcome value
3. XP accumulation and evidence of learning
4. Regret by counterfactual gap
5. Regret on 2 vs. 8 pre-selection trials, controlling for counterfactual gap
6. Minecraft frequency predicting average regret, controlling for total XP
7. Response time predicting regret, controlling for outcome value
8. Regret when the better alternative was adjacent to the chosen block

## Dataset Structure

The dataset is in long format.

Each row represents one trial for one participant. Each participant contributes multiple trials, so most trial-level analyses should account for repeated observations within participants.

Example structure:

```text
participant 1, trial 1
participant 1, trial 2
participant 1, trial 3
...
participant 1, trial 66
participant 2, trial 1
...
```

## Key Trial-Level Variables

| Variable | Description |
|---|---|
| `prolific_pid` | Participant identifier |
| `biome` | Minecraft biome/context for the trial |
| `feedback` | Feedback condition generated by the experiment |
| `comparison_type` | Counterfactual comparison type; `bad_to_good` means the participant received a worse outcome than the best alternative |
| `salience_count` | Number of blocks pre-selected before the final choice, usually 0, 2, or 8 |
| `choice` | Final block selected by the participant |
| `choice_rt` | Response time for the final choice |
| `consider_set` | Ordered set of blocks pre-selected before the final choice |
| `outcome_kind` | Actual outcome received, in words |
| `outcome_value` | Actual outcome received, coded numerically |
| `best_alt_block` | Block number of the best unchosen alternative |
| `best_alt_kind` | Best unchosen alternative, in words |
| `best_alt_value` | Best unchosen alternative, coded numerically |
| `best_alt_adjacent` | Whether the best unchosen alternative was adjacent to the chosen block |
| `xp` | Running cumulative score |
| `regret` | Participant's self-reported regret rating for the trial |
| `trial_index` | Trial number |

## Derived Variables Used in Current Analyses

### Counterfactual gap

The current analysis creates:

```r
counterfactual_gap = best_alt_value - outcome_value
```

This captures how much better the best unchosen alternative was than the outcome the participant actually received. Larger positive values indicate a larger missed opportunity.

### Best alternative is diamond

The current analysis also creates:

```r
best_alt_is_diamond = best_alt_kind == "diamond"
```

This can be used to test whether missing a diamond has a unique relationship with regret.

### Logged response time

The response time analysis creates:

```r
log_choice_rt = log(choice_rt)
```

This is used because response times are usually skewed, and logging response time reduces the influence of very long trials.

## Current Models

### Regret by actual outcome value

```r
model_regret_outcome <- lmer(
  regret ~ outcome_value + (1 | prolific_pid),
  data = data_processed
)
```

This tests whether participants report more regret after worse outcomes.

### Regret by counterfactual gap

The current file visualizes the relationship between regret and counterfactual gap using boxplots, jittered points, linear smooths, and mean regret with standard errors.

### Regret on 2 vs. 8 pre-selection trials

```r
btg_gap <- data_processed %>%
  filter(
    comparison_type == "bad_to_good",
    salience_count %in% c(2, 8)
  ) %>%
  mutate(
    salience_count = factor(salience_count, levels = c(2, 8)),
    counterfactual_gap = best_alt_value - outcome_value
  )

model_btg_gap <- lmer(
  regret ~ salience_count + counterfactual_gap + (1 | prolific_pid),
  data = btg_gap
)
```

This tests whether regret differs between 2-block and 8-block pre-selection trials among `bad_to_good` trials, while controlling for the size of the missed opportunity.

### Minecraft frequency and average regret

The analysis creates a participant-level dataset:

```r
minecraft_regret <- data_processed %>%
  group_by(prolific_pid) %>%
  summarise(
    mean_regret = mean(regret, na.rm = TRUE),
    total_xp = max(xp, na.rm = TRUE),
    minecraft_freq_1mo = first(minecraft_freq_1mo),
    .groups = "drop"
  )
```

Then it tests:

```r
model_minecraft_regret <- lm(
  mean_regret ~ minecraft_freq_num + total_xp,
  data = minecraft_regret
)
```

This asks whether people who play Minecraft more often report more average regret, controlling for total XP.

### Response time and regret

```r
model_rt_regret <- lmer(
  regret ~ log_choice_rt + outcome_value + (1 | prolific_pid),
  data = rt_model_data
)
```

This tests whether longer response times are associated with greater regret, controlling for actual outcome value.

### Adjacency and regret

```r
model_adjacency_full <- lmer(
  regret ~ best_alt_adjacent + counterfactual_gap + (1 | prolific_pid),
  data = data_processed %>%
    filter(
      feedback == "full",
      salience_count %in% c(2, 8),
      comparison_type == "bad_to_good"
    ) %>%
    mutate(
      counterfactual_gap = best_alt_value - outcome_value
    )
)
```

This tests whether regret is greater when the better unchosen alternative was adjacent to the chosen block, controlling for counterfactual gap.

Note: in the current R Markdown file, the adjacency visualization calls `model_adjacency`, but the model object created above is named `model_adjacency_full`. The visualization should use:

```r
plot_model(
  model_adjacency_full,
  type = "pred",
  terms = "best_alt_adjacent"
)
```

## Modeling Notes

Because the dataset is trial-level, most trial-level models should include a random intercept for participant:

```r
(1 | prolific_pid)
```

This accounts for repeated trials within the same person.

Participant-level predictors, such as Minecraft frequency, should be analyzed using a participant-level dataset with one row per participant.

## Current Exploratory Questions

The current analysis addresses these questions:

1. Does regret change over the course of the task?
2. Do participants regret worse outcomes more?
3. Is there evidence of learning from XP accumulation or average outcome value over time?
4. Does regret increase as the counterfactual gap increases?
5. On bad-to-good trials, is regret higher after pre-selecting 8 blocks than 2 blocks, controlling for counterfactual gap?
6. Do people who play Minecraft more often experience more average regret, controlling for total XP?
7. Are longer response times associated with greater regret, controlling for outcome value?
8. Are people more regretful when the better alternative was adjacent to the chosen block?
